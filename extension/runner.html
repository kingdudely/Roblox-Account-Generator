DuckDNS record

writes the TXT for you

When you add the domain in Google Admin it shows a google-site-verification=… value. Paste it here with your DuckDNS token; this writes the record through DuckDNS's API and waits until it resolves. DuckDNS has no DNS editor — the token is the editor.

1 · Get a DuckDNS subdomain
  1. Sign in at duckdns.org and add a subdomain.
  2. Copy your account token from the same page. One token covers every subdomain.
  3. There is no DNS box in the DuckDNS UI — TXT records live behind the API. The card above is that API, so you never touch a dashboard.

2 · Create the Cloud Identity account
  1. Open the Cloud Identity Free signup: workspace.google.com/gcpidentity/signup .
  2. About you — your name and an address you can still read later. It must not be on the tenant domain; a personal Gmail is what this field is for. It is only the recovery address.
  3. About your business — any company name, and your country.
  4. Your Cloud Identity domain — enter <sub>.duckdns.org. The subdomain must already exist at duckdns.org.
  5. Create your admin account — choose a username and password. This creates admin@<sub>.duckdns.org. There is no separate Google account to make first; this is the tenant's first user.
  6. Verify the domain — Google shows a google-site-verification=… value. Paste it into the DuckDNS card above, press Write record, then click Verify back in the signup tab. If Google says it cannot find the record, wait a minute and retry.
  7. Accept the Cloud Identity Agreement. You land in the Google Cloud console with the tenant live.

If signup stops at a QR instead of a phone field, use the Phone gate card just below — it reads the destination number and the exact message to send. The line must be able to send SMS; receive-only numbers fail.

Already have a Workspace tenant? Skip the signup and add the free edition from Billing → Cloud Identity Free , adding the domain at Domains .

If Google answers “Cloud Identity does not currently support this domain name”, use a domain you own at a registrar instead — every later step is identical.

3 · Authenticator setup

The admin needs an enrolled second factor so the tenant is not half-configured. The authenticator below is local: it turns the setup secret into the current 6-digit code, so no phone or app is needed. Per-identity backup codes are minted through the Admin API. Enforcement has to be On with SMS and phone call removed from the allowed methods — that is the setting that stops Google offering a phone number at every fresh account's first sign-in.

  1. Sign in as the tenant admin and open myaccount.google.com → Security → 2-Step Verification .
  2. Choose Authenticator app (not SMS), then click Can't scan it? and copy the secret key. Paste it below and use the live code to finish Google's setup.
  3. Open Admin console → Security → Authentication → 2-Step Verification for the OU that holds the identities and set Enforcement to On, with Methods set to Any except verification codes via text, phone call. With enforcement off, a fresh account has no second factor, so Google falls back to “Enter a phone number to get a text message”. With SMS disallowed, it offers the authenticator instead and the run enrols it.
  4. The run mints ten one-time codes per identity with verificationCodes.generate before opening the Roblox tab and keeps them on the identity and the account export. At the sign-in the Google content script accepts the new-account terms, enrols the authenticator app (secret saved as otp_secret), and falls back to Try another way → Enter one of your backup codes. Mint 2SV codes on the Run tab does the same for identities that already exist.

4 · Create the key
  1. Create a project inside the tenant's organization at console.cloud.google.com/projectcreate .
  2. Enable the Admin SDK: admin.googleapis.com .
  3. OAuth consent screen → Internal; add scopes admin.directory.user, admin.directory.user.security and admin.directory.domain.readonly. Open the consent screen .
  4. Credentials → Create credentials → OAuth client ID → Desktop app → download the JSON. Open credentials .
  5. Paste that JSON into Keys → Create a key here and authorize. The domain is detected afterwards, so you can leave that field blank.

Rather not build a tenant? g_oose and kingdudely on Discord sell ready keys. Ask for client_id, client_secret and refresh_token — no domain needed.

5 · Know the limits
  • 50 identities per key, roughly 45 before Google's abuse filter answers 412. That flag is permanent per tenant — deleting users does not clear it.
  • Creation is capped at 10 users per domain per second. The extension paces itself at ~8/s.
  • One Google identity becomes exactly one Roblox account. There is no unlink.
  • Deleting an identity frees the seat; the address stays reserved for about 20 days.
  • Lanes need Firefox containers. Chrome has one cookie jar per profile, so it runs one lane.

Roblox account

finalisation defaults

Roblox generated keeps the name assigned during SSO signup. Our generator sends a random name from the local word lists with the finalise call and retries if the name is taken. The terms option performs the same acceptance POST as the I Agree button on /not-approved; turn it off if you want to review the updated agreement yourself.
